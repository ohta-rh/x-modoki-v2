# ADR-0008: 画像は S3 互換のストレージに、署名つき URL でブラウザから直接送る

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断）
- 関連: [バックエンド技術選定](../research/backend.md)、ADR-0012

## 背景

1 つの投稿に画像を 4 枚まで付ける。プロフィールにはアバターとバナーがある。Server Action の本文は既定で 1MB までなので、画像を Server Action に通せない。

2026-11-18 に確認した事実: Cloudflare R2 は 10GB まで無料で、外へ出る転送に料金がかからない。MinIO の Community Edition は保守が終わっていて、新しく使うものではない。小さいサーバーで `next/image` の最適化を動かすと CPU とメモリを使う。Vercel では変換の回数に料金がかかる。Garage と SeaweedFS の版と Docker での動作は確認できていない。

## 決定

- **画像は S3 互換のストレージに置く。** コードは AWS SDK v3 の `S3Client` だけを使い、接続先は環境変数（`S3_ENDPOINT` など）で替える
- 本番は Cloudflare R2。ローカルは Docker Compose の中の Garage
- **送り方は、署名つき URL でブラウザから直接。** Route Handler がログイン・枚数・種類・大きさを確かめて、短い期限（60 秒）の署名つき URL を出す。ブラウザがそこへ PUT し、終わったら Server Action で投稿に結びつける
- 受け付けるのは JPEG・PNG・WebP・GIF、1 枚 5MB まで
- **`next/image` の最適化は使わない**（`images.unoptimized`）。投稿に結びつけるときに、サーバーで sharp を使って決まった幅の WebP を作って置く。表示はそれを `<img>` の `srcset` で出す
- 投稿に結びつかないまま残った画像は、1 日に 1 回の掃除で消す
- 画像のキーは推測できない文字列にする。公開の読み出しは、ストレージの公開のドメインから直接行う

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| S3 互換と署名つき URL（採用） | サーバーを画像が通らない。接続先を替えるだけで、どのホスティングでも動く。R2 は転送が無料 | ローカルに S3 互換のサーバーが要る。結びつかなかった画像の掃除が要る |
| Vercel Blob | Vercel では設定が少ない | Hobby は 1GB まで。Vercel に結びつく |
| UploadThing | 作るものが少ない | 外のサービスに頼る。更新が止まり気味 |
| サーバーのディスクに置く | 追加のものが要らない | サーバーを替えると消える。本番とローカルで送り方が変わる |
| ローカルに MinIO | 情報が多い | Community Edition の保守が終わっている |
| `next/image` の最適化を使う | 設定が少ない | 小さいサーバーで重い。Vercel では料金がかかる |

## 結果

- 送る処理はローカルも本番も同じコードになる
- 最初の EPIC で、Garage のイメージが Docker Compose で動き、署名つき URL での PUT が通ることを確かめる。通らなければ SeaweedFS に替える（どちらも S3 互換なので、コードは変わらない）
- 変換した画像の分だけ、置く量が増える
- ブラウザから直接 PUT するので、バケットに CORS の設定が要る
