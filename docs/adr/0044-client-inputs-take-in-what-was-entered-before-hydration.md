# ADR-0044: 入力欄の値を状態に持つクライアントの部品は、マウントのときに DOM に入っている値を取り込む

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #47、#25、[バグのルール](../../.claude/rules/bug-handling.md) の 4 節（同じ種類の不具合が 2 回出たら、仕組みかルールで防ぐ）

## 背景

- サーバーで描いた入力欄は、React が引き継ぐ（ハイドレーション）前から操作できる。その間に入れた文字や選んだファイルは DOM には残るが、`onChange` は呼ばれないので、React の状態には入らない
- 同じ種類の不具合が 3 回出た。投稿欄の文字（#47。見えているのに投稿できない）、画像の添付（#25 で先に対応）、アバターとバナーの選ぶ欄（#25。選んだのに保存されない）
- 3 回とも、画面のテスト（`goto` の直後に入力する）で見つかった。遅い回線では人でも起きる（#47 の記録）

## 決定

- **入力欄（`<input>`・`<textarea>`、ファイルを含む）の値を状態に持つクライアントの部品は、マウントのときに DOM の値を一度だけ読み、空でなければ状態に取り込む。** そのあとの変化は `onChange` で受ける
- **その部品の単体のテストに、`renderToString` で描いた HTML の入力欄に値を入れてから `hydrateRoot` し、値が状態に入ることを確かめるテストを置く**（`compose-box.test.tsx`、`image-attachments.test.tsx`、`profile-image-picker.test.tsx` の形）
- 状態に持たない入力欄（`FormData` で送るだけのもの）は対象の外。DOM の値がそのまま送られる
- `.claude/rules/architecture-fsd.md` と `.claude/agents/code-reviewer.md` に書き、レビューで確かめる

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **マウントのときに DOM の値を取り込む（採用）** | 小さく、部品の中で閉じる。単体のテストで確かめられる | 部品ごとに数行と 1 つのテストが要る |
| ハイドレーションが終わるまで入力欄を無効にする | 取りこぼしが起きない | 読み込みの遅い端末で、しばらく入力できない。X の操作感から外れる |
| 入力欄を状態に持たず、送るときに DOM から読む | 取りこぼしが起きない | 文字数の数え方・ボタンの有効や無効・プレビューのように、入力中に使う値が要る部品では使えない |
| 何もしない（画面のテストだけで見つける） | 手間が無い | 3 回見つかったあとも、新しい部品で同じことが起きた |

## 結果

- 良くなること: 読み込みの直後に操作しても、見えているものとアプリの持っているものが食い違わない
- 受け入れる負担: 入力欄を状態に持つ部品を足すたびに、マウントの取り込みとそのテストを書く
- 守ること: 入力欄を状態に持つ新しい部品は、この取り込みとテストが無ければレビューで差し戻す
