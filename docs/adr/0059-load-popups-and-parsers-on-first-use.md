# ADR-0059: メニュー・ダイアログ・ホバーカード・トーストと投稿の解析は、使うときに読み込み、最初に送る JavaScript を e2e で 200KB 以下に保つ

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #32、NFR-PERF-05、ADR-0014（shadcn/ui と Base UI）、[速さの調べ](../research/performance-m1.md)

## 背景

2026-11-19 に、ログインした `/home` の HTML が読むスクリプトを gzip して数えた。合計は 329KB で、予算（NFR-PERF-05）は 200KB。`next analyze`（Next.js 16.4.6）で中身を分けると、次のとおりだった（部品ごとの gzip の和）。

- Next.js と React の土台: 約 175KB。どの画面にも要る
- Base UI と floating-ui: 約 104KB。メニュー・ダイアログ・ホバーカード・トースト・タブ・ツールチップ。開くまで要らない
- twitter-text と、それが連れてくる core-js: 約 35KB。本文のリンクの切り出しと、投稿の文字数の数え
- zod と t3-env: 約 32KB。`@/shared/config` の入口が `env` も出していて、クライアントの部品がこの入口を読んでいた。`createEnv` は読んだときに動くので、使わなくても残る

ほかに分かったこと:

- Next.js 16 の `next build` は、画面ごとの JavaScript の量を出さない。NFR-PERF-05 の「`next build` の出力」では確かめられない

## 決定

- **開くまで要らない部品は、使う人が手を伸ばしたときに読み込む。** 部品は `src/shared/ui/` に kit と同じ名前で置く
  - `dropdown-menu`: 押すまではただのボタン（`aria-haspopup="menu"`）。かざしたりフォーカスしたりすると、部品を先に読む。押すか ↓・↑ キーで、本物に入れ替えて開く。先に読むときは入れ替えない（入れ替えると、キーボードで来た人のフォーカスが消える）
  - `dialog`: `open` が初めて `true` になったときに読む。開いたまま描かれるルートのモーダル（投稿・画像・プロフィールの編集）は、今のまま kit を使う
  - `toast`: `toast.add` は知らせを溜めるだけで、最初の知らせのときに部品を読む
  - ホバーカード（`entities/user`）: かざすまではただのリンクで、かざすと部品を読む。0.5 秒かざしたままなら、本物に入れ替えて開く
- **投稿のリンクは、サーバーで見つけて DTO の `links` で渡す。** ブラウザは本文をそこで切るだけにする。文字数の数えは、入力欄に触れたとき（または最初から本文があるとき）に読む。twitter-text を使うものは `@/shared/lib/text-parse` に、ブラウザがすぐ読むものは `@/shared/lib/text` に分ける
- **`env` は `@/shared/config/index.server`（`server-only`）からだけ出す**
- **最初に送る JavaScript の量は、e2e のテストで確かめる**（`e2e/performance.spec.ts`: ログインした `/home` の HTML の `<script src>` を、`noModule` を除いて 1 回ずつ取り、gzip した和が 200KB 以下）。バイトの量は揺れないので、CI で毎回流す

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **使うときに読む（採用）** | Base UI の振る舞いとアクセシビリティをそのまま使える | 初めて開くときに、部品が届くまでのわずかな待ちがある。部品の入れ替えの分、作りが増える |
| メニューやダイアログを自前で書く | 量が最も小さい | フォーカスの管理・キーボードの操作・位置合わせを全部作り直すことになり、誤りやすい |
| 予算をゆるめる | 手間が無い | 要件を弱めることになる |
| ネイティブの popover と dialog に替える | 量が小さい | Base UI と見た目・振る舞いがずれる。Safari の対応を確かめ直す必要がある |

## 結果

- 良くなること: ログインした `/home` の最初の JavaScript は 194KB（gzip）になった。プロフィール 196KB、検索 195KB、通知 174KB（2026-11-19）
- 受け入れる負担: 初めてメニューなどを開くとき、部品が届くまでのわずかな待ちがある（かざすかフォーカスで先に読むので、多くの場合は押す前に届く）。新しい部品の入れ替えの作りを、テストで守り続ける
- 守ること:
  - 画面に最初から出る部品から、`@/shared/ui/kit` の入口・Base UI・twitter-text を直に読まない。読むときは上の部品か動的な `import()` を通す
  - e2e の予算のテストが落ちたら、予算を上げずに、何が増えたかを `next analyze` で調べて減らす
