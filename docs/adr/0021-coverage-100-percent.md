# ADR-0021: テストのカバレッジは 100% を必須とし、測れない非同期の Server Component だけを薄くして外す

- ステータス: 採用（外すファイルのパスを ADR-0022 で置き換え）
- 日付: 2026-11-18
- 決定者: ユーザー（100%）／エージェント（測る範囲と外すもの）
- 関連: ADR-0010、ADR-0013、ADR-0020、[アプリケーションの構造](../architecture/application-structure.md)

## 背景

ユーザーは 2026-11-18 に「カバレッジは 100%」と指示した。

Vitest は非同期の Server Component を動かせない（Next.js の公式の案内。ADR-0013）。非同期の Server Component を含むファイルは、Vitest のカバレッジでは 0% になる。Next.js 16 のビルドは Turbopack で、画面を通したテストの間のサーバー側のカバレッジを取る確かな方法を確認できていない。

つまり、全部のファイルを 1 つの数字で 100% にすることはできない。できるのは、測れないファイルを、中身が無いほど薄くすること。

## 決定

- **Vitest のカバレッジ（V8）のしきい値は、行・分岐・関数・文の 4 つとも 100%。** 下回ったら CI が落ちる（ADR-0020）
- **測る対象は `src/` の全部。** テストから読まれていないファイルも数える（`coverage.include` に `src/**` を書く）
- **外してよいのは次の 4 種類だけ。** 一覧は `vitest.config.ts` の 1 か所に、理由と一緒に書く

| 外すもの | 理由 | 代わりの確認 |
|---|---|---|
| `src/app/**/page.tsx`・`layout.tsx`・`default.tsx` | 非同期の Server Component。Vitest で動かせない | 全てのページに、Playwright のテストを 1 つ以上書く |
| `src/components/ui/**` | shadcn/ui から取り込んだコード（ADR-0014） | 使う側のテストと Playwright |
| `src/server/db/schema/**` | 表の宣言だけで、動く分岐が無い | マイグレーションを流す・データアクセス層のテスト |
| `**/*.d.ts`、型だけのファイル | 動くコードが無い | 型の確認 |

- **外したファイルに、判断を書かない。** `page.tsx`・`layout.tsx`・`default.tsx` がしてよいのは、引数を読む、データアクセス層を呼ぶ、結果を同期のコンポーネントへ渡す、`<Suspense>` で包む、まで。条件での出し分け・整形・計算は、同期のコンポーネントか `lib/` に書く
- **非同期の Server Component は `src/app/` の中だけに書く。** `src/features/*/components/` は全部、同期のコンポーネントにする
- Route Handler（`route.ts`）・Server Action・データアクセス層・`proxy.ts` は外さない。Vitest で、本物の PostgreSQL に対して試す
- `/* v8 ignore */` などの、行を数えさせない書き方を使わない。届かない行は消す
- 外すものを足す・しきい値を下げるときは、新しい ADR を書く
- 画面を通したテストは、カバレッジの数字に入れない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 100% とし、測れないファイルだけを薄くして外す（採用） | しきい値が単純で、ごまかせない。判断のあるコードは全部テストされる。構造の決まり（薄いルート）がテストで守られる | テストを書く量が多い。例外の一覧を保つ必要がある |
| 外すものを作らず、全部を 100% | 例外が無い | 非同期の Server Component が測れないので、達成できない |
| 画面を通したテストのカバレッジを足して 100% | ページも数字に入る | Turbopack のビルドでサーバー側を測る確かな方法を確認できていない |
| 80〜90% のしきい値 | 書く量が減る | 指示に反する。「どの 10% を残すか」の議論が毎回起きる |
| 変えた行だけ 100% | 新しいコードは守られる | 全体の数字が保証されない |

## 結果

- 判断を含むコードは、必ずテストを通る
- ページとレイアウトが薄くなり、表示の中身は同期のコンポーネントとして単体で試せる
- 例外の扱いや、起こりにくい分岐にもテストが要る。書けない分岐は、要らない分岐として消す
- 「100%」は、Vitest が測れる範囲の 100% という意味。ページ・レイアウト・取り込んだ部品・表の宣言は数字に入らず、Playwright と使う側のテストで確かめる
