# ADR-0037: リクエストごとの接続の pool は、after() で閉じず、使わなくなって 1 秒で接続を閉じる

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: ADR-0017（リクエストごとに 1 つ、`cache()` で共有する決定は変えない）、[Better Auth の調査](../research/better-auth-on-next-16.md) の 4 節、#18

## 背景

#10 の調査で動いた `getDb()` は、リクエストごとに `Pool` を作り、`after(() => pool.end())` で閉じていた。

#18 で、ログインした画面（部分的なプリレンダー）と Server Action を本物のサーバーで動かすと、Better Auth のセッションの読み取りとログアウトが `Cannot use a pool after calling end on the pool` で失敗した。

- `getDb()` の中に一時的なログを入れて再現すると、1 つのリクエストの中で pool が 3 つ作られ、そのうちの 1 つが `after()` で閉じられたあとに、セッションの読み取りがその pool を使って失敗していた
- Next.js 16.4.6 の文書（`after.md`）は、`after()` の処理が「応答**かプリレンダー**が終わったあと」に動くと書いている。1 つのリクエストの中に、`after()` が動く区切りが 1 つではない

## 決定

- **`getDb()` の pool は `end()` しない。** `idleTimeoutMillis: 1_000` で、使わなくなった接続を 1 秒で閉じさせる（`max: 2` は変えない）
- `pg` の `Pool` は、接続を閉じたあとも、次の問い合わせで接続を作り直す。閉じた pool を使う誤りは起きない
- リクエストごとに 1 つの pool を `cache()` で共有し、モジュールの一番上で作らないことは変えない（ADR-0017）

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| `after()` で閉じず、1 秒で接続を閉じさせる（採用） | 閉じた pool を使う誤りが原理的に起きない | 接続が最大 1 秒残る |
| `after()` で閉じたまま、プリレンダーの中で `getDb()` を呼ばない | 接続がすぐ閉じる | どこでプリレンダーが走るかに頼り、見落とすと本番で落ちる |
| モジュールの一番上で 1 つの pool を持つ | 速い | Workers で禁じられている（ADR-0017） |

## 結果

- マイルストーン 2（Workers と Hyperdrive）で、リクエストをまたいで残る接続のタイマーが許されるかを、最初の PBI で確かめる。許されなければ、この ADR を置き換える
- `getDb()` のテストは、使わなくなった接続が閉じ、そのあとも問い合わせができることを確かめる
