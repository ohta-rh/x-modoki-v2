# ADR-0019: 最初のマイルストーンは「ローカルで全部が動く」とし、Cloudflare への配備はその次にする

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: ユーザー
- 関連: ADR-0003、ADR-0017、ADR-0020、ADR-0021、[機能の範囲](../architecture/scope.md)

## 背景

本番は Cloudflare Workers に決まった（ADR-0017）。ただし、Workers の上での Cache Components・`proxy.ts`・Better Auth の動作は確かめられていない。配備の確認を先にすると、機能を作る前に、動くかどうか分からない部分に時間を使うことになる。

ユーザーは 2026-11-18 に「いったんは『ローカルで動く』をマイルストーンにする」と指示した。

## 決定

- **マイルストーン 1 は「ローカルで全部が動く」。** 終わりの条件は次の 3 つ
  - [機能の範囲](../architecture/scope.md) の「最初の版に入れる」機能が、`docker compose up -d` と `pnpm dev` で全部動く
  - CI が通っている（ADR-0020）
  - カバレッジが 100%（ADR-0021）
- **マイルストーン 2 は「Cloudflare で動く」。** Workers への配備、Hyperdrive、R2、Cron Triggers、配備の自動化を作る
- マイルストーンは GitHub のマイルストーンとして持ち、EPIC と PBI をそこに付ける（ADR-0003）
- マイルストーン 1 の間も、Workers で動かないものをサーバーのコードに入れない（ADR-0017 の制約）。確かめるのはマイルストーン 2 の最初の PBI（`opennextjs-cloudflare preview` での確認）
- マイルストーン 1 では、Cloudflare のアカウント・Wrangler の設定・本番の秘密の値を必要としない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ローカルで動かしてから配備（採用） | 機能を先に作れる。外のアカウントが要らない | Workers で動かない部分が、後で見つかる恐れがある |
| 最初に配備の骨組みを作る | Workers での問題が早く見つかる | 機能が無いうちに、確かめられていない部分に時間を使う。ユーザーの指示に反する |
| マイルストーン 1 の CI に OpenNext のビルドだけ入れる | 動かないものを早めに見つけられる | ビルドが通っても動くとは限らない。CI が遅くなる |

## 結果

- マイルストーン 1 は、Docker とリポジトリだけで完結する
- Workers で動かないものが、マイルストーン 2 で見つかる恐れがある。ADR-0017 の制約を lint とレビューで守ることで減らす
- マイルストーン 2 の最初の PBI で、動かないものを洗い出し、ADR を書いて替える
