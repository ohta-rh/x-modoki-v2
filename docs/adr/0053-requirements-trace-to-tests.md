# ADR-0053: 全部の要件を、通っているテストに結びつけ、CI の最初の確認で確かめる

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #30、ADR-0020（CI）、ADR-0021（カバレッジ）

## 背景

- カバレッジ 100% は行と分岐が動いたことしか言わず、要件を確かめたことは言わない（#30）
- 要件は `docs/requirements/functional.md`（106）と `non-functional.md`（38）の 144 個。2026-11-19 の時点で、テストの名前や説明で要件の ID を持つものは 10 個だった
- 要件の表の「満たす PBI」には、まだ開いている PBI（#31 アクセシビリティ・#32 速さ・#33 脅威の対策・#37 依存）が受け持つものがある

## 決定

- **`docs/requirements/traceability.md` に、要件の ID ごとに 1 行、確かめるテストを `` `ファイル` › テストの名前 `` で書く。** ルーティングの 1 節の URL ごとにも 1 行、Playwright のテストを書く
- **テストのすぐ上に `// FR-POST-01: …` の形で ID を書く。** `grep -rn FR-POST-01 src e2e scripts` で ID からテストを引ける
- **`scripts/check-traceability.mjs` が、行の抜け・無いファイル・無いテストの名前・ID を持たないテスト・e2e でない URL のテストを指摘する。** `pnpm docs:check`（CI の最初の確認）で流す
- **あとの PBI が受け持つ要件だけは、テストの代わりに `#31 で確かめる` と書ける。** 要件の表の「満たす PBI」がその番号を含むときに限り、スクリプトが確かめる。その PBI が、テストを足して行を書き直す

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **表とテストのそばの ID、スクリプトで確かめる（採用）** | 抜けとずれが CI で落ちる。テストの名前を変えなくてよい | 表を手で書く |
| テストの名前に ID を入れる | `grep` だけで足りる | 144 個のテストの名前が変わり、過去の試験レポートの名前とずれる |
| 表だけ（確かめない） | 手軽 | 書いたテストが消えても気づかない |

## 結果

- 良くなること: 要件ごとに、どのテストが確かめているかが分かり、消えれば CI が落ちる
- 受け入れる負担: テストの名前を変えたら表も直す（スクリプトが知らせる）
- 守ること: 要件を足すとき、受け持つ PBI が表の行を書く。`#NN で確かめる` は、その PBI が終わるときに必ずテストに書き直す
