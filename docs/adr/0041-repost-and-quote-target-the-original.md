# ADR-0041: リポストと引用の対象は、リポストの行なら元の投稿、返信ならその返信にする

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: ADR-0015、[データモデル](../architecture/data-model.md) の 2 節、#22

## 背景

- リポストは `posts` の 1 行で、本文が空、`repost_of_id` が元を指す（ADR-0015）。CHECK の制約で、リポストの行は `reply_to_id` と `quote_of_id` を持てない
- 一覧では、リポストの行は元の投稿のカードとして出る。そのカードの操作は元の投稿に対して行う（#22 の受け入れ条件）
- #22 の受け入れ条件は「リポストのリポスト、返信のリポストは、元の投稿へのリポストになる」。返信の「元」が、返信そのものか、返信先（スレッドの上）かは書かれていない
- X では、返信をリポストすると、その返信がリポストされる

## 決定

- **リポストとリポストの引用は、`repost_of_id` を 1 段たどった元の投稿を対象にする。** リポストの行はリポストも引用もされない。元はリポストではないので、1 段で終わる
- **返信は、本文を持つ 1 つの投稿として、その返信自身をリポスト・引用する。** 返信先へはたどらない
- 対象の確かめ（無い・削除済みなら `NOT_FOUND`）と数の増減は、同じトランザクションの中で対象の行に対して行う

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **リポストの行だけ元へたどり、返信はそれ自身（採用）** | X と同じ。返信の中身が広がる。CHECK の制約とも合う | 受け入れ条件の文言の片方を、解釈で読むことになる |
| 返信も返信先（スレッドの最初）へたどる | 文言をそのまま読める | 押した投稿と違う投稿がリポストされ、利用者が驚く。返信の内容が広がらない |
| リポストの行もそのままリポストする | 作りが簡単 | 本文の空なリポストのリポストが連なり、一覧に意味のない行が出る |

## 結果

- 良くなること: リポストのカードで押しても、元の投稿のカードで押しても、同じ 1 つのリポストになる（同じ人が 2 回できない一意の索引とも合う）
- 受け入れる負担: #22 の受け入れ条件の「返信のリポスト」は、この ADR の読み方で確かめる
- 守ること: リポストの行を対象にする操作（いいね・ブックマーク・返信も同じ）は、画面に出ている元の投稿の ID で行う
