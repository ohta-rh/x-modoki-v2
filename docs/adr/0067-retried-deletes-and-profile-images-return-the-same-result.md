# ADR-0067: 削除とプロフィールの画像の保存は、やり直しても同じ結果を返す

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #88、#84、#34、ADR-0064、ADR-0066（置き換える）

## 背景

- ADR-0066 で、作者がもう消した自分の投稿の削除を成功にした（#84）
- 6 巡目の探索的テストで、プロフィールの保存でも同じ種類が見つかった。新しいアバター（またはバナー）の保存の応答だけが失われると、画像はもう保存されているのに、やり直しは `sealUploads` が保留中でない画像を断るので「画像を保存できませんでした」になった（#88、2026-11-19 に 3 回再現）
- いいね・ブックマーク・リポスト・フォロー・固定・表示の設定は「こうする」を送る形で、投稿の作成は ADR-0064 で、もとからやり直しに耐える

## 決定

- **作者が、もう消した自分の投稿を消すと `{ ok: true }` を返す**（ADR-0066 の決定をそのまま引き継ぐ）。数と通知はもう変えない。無い投稿と他人の消された投稿は `NOT_FOUND`
- **プロフィールの保存で、送られた画像の ID が、この人の ready の画像で、その `key` がこの人の今のその欄（アバターは `image`、バナーは `banner`）と同じなら、その欄はもう保存済みとして取り込まない。** ほかの欄（名前・自己紹介・場所・URL）は保存して `{ ok: true }` を返す
- それ以外の取り込み済みの画像（別の欄の画像、置き換えられて使われていない画像、他人の画像）は、今までどおり断る
- 新しい変更の操作を足すときは、応答だけが失われたやり直しで同じ結果になるかを確かめる

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **サーバーで、もうその人のものになっている結果を成功にする（採用）** | どの画面も同じ結果を受け取る。別のタブで先に保存したあとも同じ | 「もう保存済みだった」と「今保存した」を見分けない |
| 画面で失敗を成功として扱う | サーバーを変えない | 本当の失敗（他人の画像など）まで成功に見える |
| 要求ごとの鍵を足す | 中身によらず見分ける | 列と移行と、全部の呼び出しに鍵を通す手間（ADR-0064 で退けた案と同じ） |

## 結果

- 良くなること: 全ての変更の操作が、応答だけが失われたやり直しで同じ結果になる
- 受け入れる負担: 保存のたびに、この人の行と画像の行を 1 回ずつ多く読む
- 守ること: 新しい変更の操作を足すときは、この ADR の確かめ方（応答だけを切ってやり直す e2e）を足す
