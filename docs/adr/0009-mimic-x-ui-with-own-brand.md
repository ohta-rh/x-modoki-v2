# ADR-0009: UI と操作は X の Web 版に合わせ、名前・ロゴ・アイコン・フォント・データは自前のものにする

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: ユーザー（X に可能な限り合わせる）／エージェント（使わないものの線引き）
- 関連: [X の Web UI/UX 調査](../research/x-uiux.md)、[UI/UX 仕様](../architecture/ui-ux.md)、ADR-0014

## 背景

ユーザーは「UI/UX は可能な限り X を模倣する」と指示した。

X の Web 版はログインしないと見られない部分が多く、2026-11-18 の調査で出典から確認できた値は限られる（列の幅 275 / 600 / 350px、右サイドバーの sticky、文字数の数え方、背景の色の一部）。ブレークポイント・配色の多く・キーボード操作の一覧は、広く報告されている近似の値にとどまる。

X の開発者向けの表示の要件は、X との誤った関係を思わせること、実在しない投稿の見本を作ること、投稿を変えて見せることを禁じている。ロゴの利用は公式のブランドの資料に従うことが求められている。

## 決定

- **合わせるもの**: 3 カラムの骨格と列の幅、sticky で半透明のヘッダー、タブ、投稿カードの並びと操作の列、スレッドの線、3 つのテーマとアクセントの色、モーダルになる URL の形（`/compose/post`、`/{username}/status/{id}/photo/{n}`）、文字数の数え方（`twitter-text`）、ボタンのホバーの振る舞い、キーボード操作
- **使わないもの**: 「X」「Twitter」の名前とロゴ、Chirp フォント、X のアイコン・画像・アニメーションの素材、X のスクリーンショット、実在の投稿やアカウントを装うデータ
- アプリの表示の名前は「x-modoki」。ロゴは自前のもの、アイコンは Lucide、フォントは OS のフォントを使う
- フッターとログインの画面に「X Corp. とは関係の無い学習用のアプリ」と書く
- 開発用のデータは、全部自分で作った架空のものにする
- X にしか無い製品（Grok・Premium・認証済み組織・Communities・広告・収益化）は作らない
- 確認できていない値（ブレークポイントなど）は Tailwind の標準の値に丸め、見た目で調整する。値と確度は [UI/UX 仕様](../architecture/ui-ux.md) に書く
- 色とアクセントは CSS の変数で持ち、1 か所で替えられるようにする

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 見た目と操作は合わせ、名前・ロゴ・素材は自前（採用） | ユーザーの指示に合う。X の素材と名前を使わないので、公式と間違われにくい | 配色まで同じにするので、公開の場に出すと見た目が似ていることを指摘される恐れが残る |
| ロゴ・アイコン・フォントも同じにする | 最も似る | 商標と著作物を無断で使うことになる |
| 骨格だけ合わせ、配色とアクセントは変える | 最も安全 | 「可能な限り模倣」の指示に届かない |
| 独自の UI にする | 自由 | 指示に反する |

## 結果

- 学習用として、X の Web 版の作りを細かく再現する
- 公開の場（誰でも登録できる形）に出すときは、その前にアクセントの色と表示の名前を見直す。色は変数なので 1 か所で替えられる
- この ADR は法的な助言ではない。商用で使うときは、専門家に確かめる
