# ADR-0064: 同じ人が 1 分以内に同じ投稿をもう一度送ったら、新しく作らずに前の投稿を返す

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #76、#70、#34

## 背景

- #70 で、通信の失敗は「通信できませんでした。もう一度お試しください」と出し、文字を残すようにした。応答だけが失われた（サーバーは投稿を作った）ときにもう一度押すと、同じ投稿が 2 つできた（#76、2026-11-19 に 2 回ずつ再現）
- いいね・ブックマーク・リポスト・フォローは「こうする」を送る形なので、やり直しても重ならない。重なるのは投稿・返信・引用の作成だけ
- 画面は送っている間ボタンを押せない（`useTransition`）ので、同時に 2 つ届くことは無い。やり直しは前の要求が終わったあとに届く
- X は、同じ人の同じ本文の投稿を続けて受け付けない

## 決定

- **`createPost` は、入れる前に、同じ作者・同じ本文（NFC にそろえて前後を削ったあと）・同じ返信先・同じ引用元・同じ画像の並びで、消されていない 60 秒以内の投稿を探す。あれば、新しく作らず、その ID で `{ ok: true }` を返す**
- 投稿の数・親の返信の数・通知は、前の投稿の分だけ（増やさない）
- 鍵の列（要求ごとの ID）は足さない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **同じ中身の 60 秒以内の投稿を返す（採用）** | 列も移行も要らない。画面は何も変えない。X の重複の扱いに近い | 1 分以内にわざと同じ投稿を 2 回したいときも 1 つになる |
| 画面が要求ごとの鍵を作り、`posts` に一意の列を足す | 中身によらず正確に見分ける | 列と索引の移行、画面の 10 か所の呼び出しに鍵を通す手間 |
| 同じ本文を「既に投稿しました」と断る | 重ならない | 応答が失われた人には、投稿できたのか分からない |
| そのままにする | 手間が無い | 通信の弱い所で同じ投稿が並ぶ |

## 結果

- 良くなること: 応答が失われたあとのやり直しでも、投稿は 1 つ。画面には成功として出る
- 受け入れる負担: 1 分以内の、同じ人の、全く同じ投稿は 1 つにまとまる。投稿のたびに、作者の索引で 1 回の検索が増える
- 守ること: 投稿の作り方（本文の整え方・画像の結び方）を変えるときは、この見分けの条件もそろえる。同時に届く 2 つの要求を見分ける必要が出たら（画面以外からの投稿など）、鍵の列の案で置き換える
