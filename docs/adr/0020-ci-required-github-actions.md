# ADR-0020: CI を必須とし、GitHub Actions で全部の確認を push と PR のたびに動かす

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: ユーザー（CI は必須）／エージェント（中身）
- 関連: ADR-0005、ADR-0013、ADR-0019、ADR-0021、[環境と配備](../architecture/environments.md)

## 背景

このリポジトリは `main` に直接 push して進める。レビューで止める場所が無いので、手元で確認を飛ばした変更がそのまま `main` に入る。エージェントが作業することが多く、「通ったはず」という報告は確認の代わりにならない。

ユーザーは 2026-11-18 に「CI は必須」と指示した。

## 決定

- **CI は GitHub Actions。`main` への push と、全ての PR で動かす**
- CI が動かす確認は次の 7 つ。1 つでも落ちたら、全体が失敗になる

| 確認 | コマンド |
|---|---|
| ドキュメント（OKF の形・リンク・ADR のステータス） | `pnpm docs:check` |
| 型 | `pnpm typecheck` |
| lint | `pnpm lint` |
| 整形 | `pnpm format:check` |
| 単体とデータアクセス層のテスト、カバレッジ（ADR-0021） | `pnpm test --coverage` |
| ビルド | `pnpm build` |
| 画面を通したテスト | `pnpm test:e2e` |

- テストは、CI の中の PostgreSQL と S3 互換のストレージ（サービスのコンテナ）に対して動かす。偽物にしない（ADR-0013）
- **CI が通っていない変更は、完了としない。** PBI の受け入れ条件に「CI が通っている」を必ず入れる
- **手元で同じ確認（`pnpm verify`）を通してから push する。** push のあと、CI の結果を最後まで見る
- `main` の CI が落ちたら、ほかの作業より先に直す。直せないなら、その commit を取り消す
- 確認を弱めて通さない。`continue-on-error`、テストの `.skip` と `.only`、`--no-verify`、落ちる確認の削除、しきい値の引き下げをしない
- CI の設定とアプリの最初の骨組みは、同じ PBI で作る。CI が無い状態で機能の PBI を始めない
- Node.js と pnpm の版は、`.nvmrc` と `packageManager` から読む（ADR-0005）。CI に版を別に書かない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| GitHub Actions で 7 つ全部（採用） | リポジトリと同じ場所。公開のリポジトリは無料。確認が 1 つも飛ばない | 画面を通したテストで、1 回が数分かかる |
| 手元の確認だけ | 速い | 飛ばしても分からない。環境の違いに気づかない |
| 画面を通したテストは夜だけ | push のたびの CI が速い | 壊れた変更が半日 `main` に残る |
| commit の前のフックだけ | push の前に止まる | `--no-verify` で飛ばせる。重い確認を入れられない |
| ブランチの保護と PR を必須にする | 落ちた変更が `main` に入らない | `main` に直接 push する進め方と合わない |

## 結果

- 「通った」は、CI の結果で示せる
- `main` に直接 push するので、落ちた変更が一度は `main` に入りうる。手元の `pnpm verify` と、落ちたら最優先で直すことで補う
- CI の時間が延びたら、並列にする・キャッシュするで縮める。確認を減らさない
- 配備を CI から行うかは、マイルストーン 2 で決める（ADR-0019）
