# ADR-0025: PBI を閉じるたびに、エビデンスつきの試験レポートを `docs/test-reports/` に残す

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: ユーザー（完了したら試験レポートをエビデンスつきで残す）／エージェント（置き場所と形式）
- 関連: ADR-0002、ADR-0023、ADR-0024（閉じるコメントに書く記録を、この ADR でレポートに置き換え）

## 背景

ユーザーは 2026-11-18 に「完了したら試験レポートを作成し、エビデンスつきで残す」と指示した。

ADR-0024 は、ブラウザで見たことを issue を閉じるコメントに文字で書くと決めていた。文字だけの記録は、実際に見たかどうかを後から確かめられない。issue のコメントはリポジトリの外にあり、clone しても付いてこない。画面の写真・コマンドの出力・CI の結果が 1 か所にまとまっていないと、「この PBI は何で確かめたか」を後から読めない。

同じ日に、起票した EPIC を Chrome で開いたところ、タスクの一覧で issue のタイトルが 2 回出る崩れが見つかった。機械の確認（`check-docs.mjs`）は通っていた。見た証拠を残す仕組みが無ければ、この種の確認は省かれても分からない。

## 決定

- **PBI を閉じる前に、試験レポートを `docs/test-reports/` に置く。** 完了の定義の 1 項目とする（ADR-0024 の一覧に足す）
- ファイルの名前は `issue-NNNN-<kebab-の要約>.md`（NNNN は 4 桁の issue の番号）。PBI に結びつかない作業は `YYYY-MM-DD-<kebab-の要約>.md`
- frontmatter の `type` は `TestReport`。`status` は `stable`
- **レポートに必ず書くもの**

| 節 | 中身 |
|---|---|
| 対象 | issue・確かめた commit・CI の実行の URL・日付 |
| 環境 | OS・ブラウザと版・Node.js・データベース・動かし方（`pnpm build && pnpm start`） |
| 判定 | 合格か不合格か。受け入れ条件の数と、満たした数 |
| 受け入れ条件ごとの結果 | 条件・確かめ方・結果・エビデンス（テストの名前か、画面の写真か、出力） |
| 自動のテスト | `pnpm verify` の最後の出力、カバレッジの 4 つの数字、Playwright のブラウザごとの通った数 |
| ブラウザでの確認 | 開いた URL・幅・テーマ・した操作・見えた結果・画面の写真。コンソールのエラーと警告の数、失敗した通信の数 |
| 見つけた問題 | 見つけたもの・直した commit・足したテスト・起票した issue。無ければ「なし」 |

- **エビデンスは `docs/test-reports/evidence/<レポートの名前>/` に置く。** 画面の写真は、確かめた幅ごとに 1 枚以上。JPEG か WebP で、1 枚 300KB まで、1 つのレポートに 12 枚まで。コマンドの出力は、レポートの本文にコードの枠で貼る（最後の 30 行まで）
- **ブラウザの画面の写真が 1 枚も無いレポートは、レポートとして認めない。** `check-docs.mjs` が落とす
- 秘密の値・実在の人の情報・ログインした自分のアカウントの画面を写さない
- レポートは、その時点の記録。あとから書き換えない。やり直したら、同じファイルに「再試験」の節を足す
- **issue を閉じるコメントは、commit・CI の実行の URL・レポートへのリンクの 3 つ。** 受け入れ条件ごとの確かめ方とブラウザの記録は、コメントではなくレポートに書く
- レポートは CI の URL を含むので、変更の commit のあとに、レポートだけの commit（`docs(test-report): …`）として足してよい。その commit の CI も緑であること
- `docs/test-reports/index.md` に、新しい順で並べる

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| リポジトリの `docs/test-reports/` に、写真と一緒に置く（採用） | clone に付いてくる。変更と同じ履歴に残る。機械で形を確かめられる | 写真の分、リポジトリが大きくなる |
| issue のコメントに書く（ADR-0024） | 追加のファイルが無い | リポジトリの外。`gh` からは写真を付けられず、文字だけになる |
| CI の成果物に残す | 自動で付く | 保存の期限で消える。ブラウザでの実際の操作の記録は入らない |
| GitHub のリリースに付ける | リポジトリが大きくならない | PBI ごとの記録にならない |
| 写真を Git LFS に置く | リポジトリが軽い | 設定と料金の枠が要る。1 枚 300KB・12 枚の上限なら、要らない |

## 結果

- 閉じた PBI の全部に、何を・どう確かめ・何が見えたかの記録が、写真と一緒にリポジトリに残る
- PBI ごとに、レポートを書く時間と、数 MB までの写真が増える。32 件で最大でも 100MB ほどに収まる上限にしてある
- 完了の定義の項目が 7 つから 8 つになる。ルールと、開いている全部の PBI の本文を、同じ変更で直す
- `type` に `TestReport` が増える
