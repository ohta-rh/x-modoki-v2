# ADR-0074: ハーネスは、短い CLAUDE.md、触ったときだけ読む決まり、手順の skill、止めるフックで組む

- ステータス: 採用
- 日付: 2026-11-20
- 決定者: エージェント（ユーザーの指示「Anthropic の最新のやり方に則り、速度・費用・精度の釣り合いを、品質を先にして」、2026-11-20）
- 関連: ADR-0072、ADR-0073、ADR-0023〜ADR-0028、[ハーネスの見直し](../research/harness-review-2026-11.md)

## 背景

- `CLAUDE.md` が 9 つのルールを `@` で取り込み、毎回約 78KB を読み込んでいた。sub agent も同じものを読む。公式の資料は、`CLAUDE.md` を 200 行未満にすること、`@` は量を減らさないこと、`paths:` のあるルールは合うファイルを開いたときにだけ読まれること、手順は skill に置くことを勧めている
- 書いた決まりがあっても、同じ間違いが繰り返した（`;` でつないだ commit が 3 回、名前でのプロセスの停止、全部をまとめたステージ）。公式の資料は、曲げられない決まりはフックにすることを勧めている
- PBI ごとに、作業の前の `pnpm verify`（約 10 分）を流し、CI を待つ間は何もしていなかった
- 根拠と数字は [ハーネスの見直し](../research/harness-review-2026-11.md)

## 決定

- **`CLAUDE.md` は要点と道しるべだけ**（約 60 行）。コマンド、進め方、ユーザーのものの境目、どの決まりがいつ読まれるか、機械が止めること
- **コードと文書の決まりは、`paths:` を付けて同じ場所に置く**: `architecture-fsd.md`・`quality-gates.md`・`tdd.md`・`documentation.md`。合うファイルを開いたときに読み込まれる
- **PBI の手順は skill に移す**: `deliver-pbi`（ループ、参照のファイルに完了の定義・コードレビュー・バグの扱い）と `file-issues`（EPIC と PBI の書き方）。元のルールのファイルは、古い ADR と試験レポートのリンクが切れないよう、移った先を指す短い案内として残す（起動のときには読まれない）
- **フックで止める**（`.claude/settings.json`）:
  - Bash の前（`scripts/guard-bash.mjs`）: 全部をまとめた `git add`、`--no-verify` と `git commit -n`、`;`・`||`・改行のあとの `git commit`/`git push`、名前でのプロセスの停止。シェルの書き方の幅（全体のオプション、パス、前置き、`bash -c`、サブシェル）を読み、読めない入力は止める
  - 編集のあと（`scripts/format-edited.mjs`）: 編集したファイルを Prettier で整える。止めない
  - `.env.local` は読まない（`permissions.deny`）
- **手順の 4（基準）は、出発点の commit の緑の CI にする。** 作業の前の `pnpm verify` は流さない。push の前の `pnpm verify` は変えない
- **CI を待つ間は、次の PBI を読むことと試験レポートを書くことだけをしてよい。** コードは書かず、ほかを push しない
- レビュアーは、範囲に `paths:` で絞られた決まりを自分で全部読む。手元の `pnpm` が動かなければ `./node_modules/.bin` を直接呼ぶ
- 確認の中身は変えない

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **短い CLAUDE.md・`paths:`・skill・フック（採用）** | 毎回読む量が約 78KB から約 4KB に。sub agent も軽くなる。繰り返した間違いを機械が止める | skill を呼ばないと手順が読まれない（`CLAUDE.md` と skill の説明で呼ぶように導く） |
| 決まりを短く書き直すだけ | 単純 | 毎回全部を読むことは変わらない。間違いは文で止まらなかった |
| ルールのファイルを skill の場所へ移し、古い道は消す | 重複が無い | 受け入れた ADR と試験レポートの約 40 のリンクが切れる |
| フックを多く足す（書き方の好みまで） | 機械が多くを止める | 公式の資料は数を少なく保つよう勧めている。好みは止めない |

## 結果

- 良くなること: 起動のたびの文脈が小さくなり、費用と時間が減る。間違いはフックが理由つきで止める。PBI ごとに約 10 分の確認が減る
- 受け入れる負担: シェルの文章の中の文字（たとえば heredoc の中の `git add -A`）でもフックが止めるので、ファイルの編集は編集の道具で行う。フックとその判定のスクリプトとテストを保つ
- 守ること: 新しい決まりは、コードか文書の場所に結びつくなら `paths:` 付きのルールに、手順なら skill に、曲げられないならフックに置く。`CLAUDE.md` は 200 行未満に保つ。同じ間違いが 2 回起きたら、決まりを長くせず確認にする
