# ADR-0042: プロフィールのルートは [username] の中のルートグループに置き、無いアカウントの 404 をそこだけに出す

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: ADR-0039、[ルーティング](../architecture/routing.md) の 2 節、#20、#23

## 背景

- #23 の受け入れ条件は、無いユーザー名で「404 の画面」。X は「このアカウントは存在しません」と出す
- `notFound()` は、いちばん近い `not-found.tsx` で受ける。`app/(main)/[username]/not-found.tsx` に置くと、`/{username}/status/{id}`（#20）の無い投稿まで「このアカウントは存在しません」になる
- ルーティングの 2 節は `[username]/layout.tsx` にバナー・プロフィール・タブを置く形を書いていた。この形だと、詳細の画面にもプロフィールのレイアウトがかかる

## 決定

- **プロフィールのページ（`page`・`with_replies`・`media`・`likes`）は `app/(main)/[username]/(profile)/` に置く。** そこの `not-found.tsx` が `_pages/profile` の「このアカウントは存在しません」を出す（ADR-0039 の薄い殻）
- **`[username]/status/…` はグループの外に置いたまま**で、無い投稿はメインのレイアウトの 404（ADR-0039）になる
- バナー・プロフィール・タブはレイアウトではなく、各ページが `_pages/profile` の同期の画面で出す。タブを移るとページごと読み直すが、ページの 1 つ目の一覧はサーバーで読む

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **`(profile)` のグループに置く（採用）** | 404 の文言がルートごとに正しい。URL は変わらない | ディレクトリが 1 段深い |
| `[username]/not-found.tsx` に置く | 浅い | 詳細の無い投稿も「アカウントが存在しない」になる |
| 404 を出さず、プロフィールの画面の中で「存在しない」を出す | not-found が要らない | 404 の扱いが画面ごとにばらける（ADR-0039 と合わない） |
| `[username]/layout.tsx` でヘッダーとタブを出す（ルーティングの 2 節の元の形） | タブを移ってもヘッダーが残る | 詳細の画面にもかかる。レイアウトで読んだデータを子と分けて持つことになる |

## 結果

- 良くなること: 無いアカウントと無い投稿が、それぞれ X と同じ 404 になる
- 受け入れる負担: タブを移るとヘッダーも描き直す
- 守ること: `[username]` の下にプロフィールのページを足すときは `(profile)` の中に置く。`status` のような投稿のルートは外に置く
