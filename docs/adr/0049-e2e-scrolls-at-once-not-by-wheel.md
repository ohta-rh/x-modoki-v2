# ADR-0049: 画面のテストは、ホイールではなく一度に動かしてスクロールする

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。`.claude/rules/bug-handling.md` の 4 節: 同じ種類の不具合が 2 回あれば仕組みにする）
- 関連: #56、#28、ADR-0024

## 背景

- `page.mouse.wheel` のスクロールは、ブラウザの中でなめらかに動き続ける。テストがその途中で位置を読むと、あとで画面が別の位置に落ち着く
- #56: 画像のビューアのテストが、動いている途中（`scrollY` 1）でクリックし、Linux の WebKit でページが上に戻ってたまに落ちた
- #28: 戻ったときの位置のテストが、重いときにホイールのスクロールがあとから続き、覚えた位置が古くなって Chromium で 6〜22px ずれて落ちた（記録した `scroll` のイベントで、テストが位置を読んだあとに 3067 → 3104 → 3251 と動いていた）
- どちらもアプリは正しく、テストの待ち方が原因だった。ホイールでスクロールすること自体を確かめるテストは無い

## 決定

- **`e2e/` では `page.mouse.wheel` を使わない。** ESLint の `no-restricted-syntax` で禁じる（`eslint.config.mjs`）
- スクロールは `page.evaluate(() => window.scrollTo / scrollBy({ …, behavior: 'instant' }))` で動かし、位置を使う前に `expect.poll` で値が落ち着くのを待つ
- ホイールそのものを確かめたいテストが要るときは、その行に理由を書いて規則を外し、`expect.poll` で位置を待つ

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **ホイールを禁じ、一度に動かす（採用）** | 位置がすぐに決まる。ブラウザや重さで揺れない | 利用者のホイールの操作そのものは確かめない（確かめたいことはスクロールの結果） |
| ホイールのあとに長く待つ | 書き方を変えない | 重いときは待つ長さが足りず、遅くもなる |
| ルールの文書だけにする | 手軽 | 2 回とも書いた本人が気づかなかった。仕組みでないと防げない |

## 結果

- 良くなること: スクロールの位置を前提にするテストが、重さとブラウザで揺れない
- 受け入れる負担: ホイールの操作の手触りは画面のテストでは確かめない
- 守ること: `e2e/` で `mouse.wheel` を使うときは、理由と `expect.poll` を付ける
