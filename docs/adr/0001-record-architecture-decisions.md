# ADR-0001: アーキテクチャ上の決定を ADR として記録する

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: ユーザー
- 関連: ADR-0002

## 背景

このリポジトリは空の状態から、人と AI エージェントが会話しながら作る。会話の中で決めたことは、次のセッションには残らない。決定の理由が残っていないと、同じ議論をやり直すか、理由を知らないまま決定を崩すことになる。

ユーザーは 2026-11-18 に「意思決定をした際は ADR を必ず残す」と指示し、同じルールを全リポジトリ共通のハーネス（`~/.claude/rules/adr.md`）にも入れた。

## 決定

- アーキテクチャ・技術選定（バージョンの系列を含む）・横断ルール（テスト方針、認証、ドキュメントの形式、issue の進め方など）を決めたら、**その決定を反映する変更と同じ commit で ADR を追加する**
- ユーザーが決めた場合も、エージェントが委任された範囲で決めた場合も、同じように書く。決定者を本文に書く
- 置き場所は `docs/adr/NNNN-kebab-title.md`。番号は 4 桁の連番で、付け直さない。形式は [template.md](template.md)、一覧は [README.md](README.md)
- 1 つの ADR には 1 つの決定だけを書く。タイトルは決定そのものを一文で書く
- **採用した ADR の決定は書き換えない。** 変えるときは新しい ADR を足し、古い ADR のステータスを「置き換え: ADR-NNNN」にする。誤字とリンク切れの修正は書き換えに当たらない
- ADR にはタスクの一覧やチェックリストを書かない。作業は GitHub の issue に書く
- 構成や技術を変える提案をする前に、既存の ADR を読む

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ADR を `docs/adr/` に置く（採用） | 決定と理由がコードと同じ履歴に残る。1 決定 1 ファイルで探しやすい | 決定のたびに 1 ファイル書く手間がある |
| commit メッセージと PR の説明だけに書く | 追加の作業が無い | 後から「今有効な決定の一覧」を作れない。置き換えの関係が追えない |
| 設計書 1 枚に全部の理由を書く | 1 か所で読める | 設計書を直すたびに過去の理由が消える。検討した選択肢が残らない |
| issue に決定を書く | 議論と近い場所に残る | リポジトリを clone しただけでは読めない。閉じた issue は探されない |

## 結果

- 「なぜこうなっているか」は ADR を読めば分かる。設計書（`docs/architecture/`）は今の姿だけを書き、理由は ADR へのリンクで示す
- 決定のたびに ADR・一覧・`docs/log.md` を同じ commit で直す必要がある
- 小さな実装上の判断（1 つのモジュールの中の名前、設計の選択を含まない不具合の修正）は ADR にしない。線引きは `~/.claude/rules/adr.md` に従う
