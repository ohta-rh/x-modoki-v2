# ADR-0031: データベースのテストは、ワーカーごとのデータベースを使い、テストごとに表を空にし、補助はリポジトリのルートの `test/` に置く

- ステータス: 採用
- 日付: 2026-11-18
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: ADR-0013、ADR-0021、ADR-0022、ADR-0030、[テストの設計](../architecture/test-strategy.md)

## 背景

ADR-0013 は、データアクセス層と Server Action を、本物の PostgreSQL に対して試すと決めた。#13 と #16 の本文は、「テストごとにトランザクションを始めて戻す」「テストのデータを作る関数を `src/shared/lib/testing/` に置く」と書いていた。

#12 の調査と #13 の設計で、次のことが分かった。

- データアクセス層の変更の関数は、自分で `db.transaction()` を使う（いいねと数の増減と通知を 1 つのトランザクションで書く。ADR-0011・ADR-0015）。テストの側でトランザクションを張ると、その中に入れ子になる。入れ子の扱いは、ドライバーと ORM の細かい振る舞いに頼ることになり、テストで確かめたいトランザクションの範囲そのものが変わる
- データを作る関数はデータベースを読み書きする。`src/shared/lib/` から `@/shared/db` を読むことは、ESLint の決まり（ADR-0022・ADR-0030）が禁じている
- `src/` の中に置いたものは、カバレッジ 100% の対象になる（ADR-0021）
- Vitest は、テストのファイルを複数のワーカーで同時に動かす

## 決定

- **データベースのテストは、ワーカーごとに別のデータベースを使う。** テストを始める前に、マイグレーションを流したひな形のデータベース（`xmodoki_test`）を 1 つ作り、各ワーカーはそこから `xmodoki_test_<ワーカーの番号>` を作って使う
- **各テストの前に、全ての表を空にする**（`TRUNCATE … RESTART IDENTITY CASCADE`）。テストの側ではトランザクションを張らない。データアクセス層のトランザクションは、本番と同じ形で動く
- テストでは `@/shared/db` の `getDb()` を、そのワーカーのデータベースへの接続を返すものに差し替える（`vi.mock`）。Drizzle そのものは偽物にしない（ADR-0013 のまま）
- **テストの補助は、リポジトリのルートの `test/` に置く。** 接続（`test/db.ts`）、データを作る関数（`test/factories.ts`。`makeUser`・`makePost` など）、`server-only` の代わり（`test/server-only.ts`）。読むときの別名は `@test/*`
- `test/` は `src/` の外なので、FSD の層にもカバレッジにも入らない。補助の振る舞いは、それを使うテストを通して確かめる
- シード（`pnpm db:seed`）にテストを頼らない。テストは、要るデータを自分で作る

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ワーカーごとのデータベースと、テストごとに表を空にする（採用） | データアクセス層のトランザクションがそのまま動く。テストが互いのデータを見ない。並列に動く | 表を空にする時間がテストごとにかかる（表は 15 ほどで、数ミリ秒） |
| テストごとにトランザクションを始めて戻す（#13・#16 の本文） | 速い | データアクセス層のトランザクションが入れ子になり、確かめたい範囲が変わる |
| 1 つのデータベースを全部のテストで使い、順に動かす | 仕組みが単純 | 並列に動かせず、遅い |
| 補助を `src/shared/lib/testing/` に置く（#13・#16 の本文） | `src/` の中に全部ある | `@/shared/db` を読めない（ESLint）。カバレッジの対象になる |
| 補助を `src/shared/db/testing/` に置く | データベースを読める | カバレッジの対象になり、テストのためのコードにテストが要る。本番のコードと混ざる |

## 結果

- テストは、互いのデータに頼らず、どの順でも、並列でも通る
- CI では、PostgreSQL のサービスのコンテナに、ひな形とワーカーの数だけのデータベースを作る
- #13 と #16 の本文を、この決定に合わせて直した（本文の先頭に更新の注）
