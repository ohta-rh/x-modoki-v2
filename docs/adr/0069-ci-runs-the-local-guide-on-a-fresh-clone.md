# ADR-0069: CI はまっさらなランナーで手順書のコマンドをそのまま流して確かめる

- ステータス: 採用
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #35、ADR-0020、ADR-0068

## 背景

- #35 の受け入れ条件は「まっさらな場所に clone して、手順書のコマンドを上から順にそのまま流すと、`/home` が開き、シードのユーザーで入れる」
- 手元で別の clone から `scripts/setup-local.sh` を流すと、同じ名前のポート（54320・3900・3902）と Docker Compose のプロジェクトがぶつかり、動いている開発の環境を壊す
- 手順書は、コマンドが変わっても誰も気づかないまま古くなる。設計書の「最初に動かすまで」もコードが入る前の設計のままだった（`docs/architecture/environments.md`、2026-11-19）
- GitHub Actions のランナーは、毎回まっさらな機械に clone する

## 決定

- CI に `fresh-clone` のジョブを足す。7 つの確認のジョブとは別に、並べて動かす
- コマンドは手順書（`docs/guides/local-development.md`）の「1. 最初の準備」と「2. 毎日の起動」の `sh` の塊から `scripts/guide-commands.mjs` で読み出し、そのまま流す。CI の YAML にコマンドを書き写さない
- 立ち上がったら、シードの人 `sample01` で Better Auth にログインし、その cookie で `/home` を開いて、その人の名前が出ることを確かめる
- `scripts/quality-gates.test.ts` で、ジョブが手順書から読み出していることと、手順書の節にコマンドがあることを確かめる

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **CI で手順書から読み出して流す（採用）** | 毎回まっさらな機械。手順書と CI がずれない | CI の時間が並べた分だけ増える（数分、7 つの確認と並べるので全体は延びない） |
| 手元で別の場所に clone して 1 回流す | すぐできる | 動いている環境とポートがぶつかる。1 回きりで、あとで壊れても気づかない |
| CI の YAML に同じコマンドを書き写す | 簡単 | 手順書を変えても CI が古いまま通る |

## 結果

- 良くなること: 手順書のコマンドが動かなくなると CI が赤になる
- 受け入れる負担: CI の実行が 1 つ増える
- 守ること: 手順書の 1 節と 2 節の見出しと `sh` の塊の形を変えるときは、`fresh-clone` のジョブと `quality-gates.test.ts` も直す
