# ADR-0024: 完了の定義に、本物のブラウザでのテストを必ず含める

- ステータス: 採用（閉じるコメントに書く記録を ADR-0025 で試験レポートに置き換え）
- 日付: 2026-11-18
- 決定者: ユーザー（必ずブラウザでテストする）／エージェント（中身）
- 関連: ADR-0013、ADR-0020、ADR-0021、ADR-0023

## 背景

ユーザーは 2026-11-18 に「必ずブラウザでのテストを行うように完了定義をする」と指示した。

これまでの決定では、完了は「`pnpm verify` が通り、CI が緑」だった（ADR-0020、ADR-0023）。その中に Playwright はあるが、どの PBI に画面のテストが要るかは PBI ごとの受け入れ条件に任されていた。単体のテストとカバレッジ 100%（ADR-0021）は、コードの行が動いたことを示すだけで、画面が崩れていないこと・押して動くこと・コンソールにエラーが出ていないことは示さない。このアプリの目的は、X の見た目と操作の再現である（ADR-0009）。

書いたテストは、書いた人が思いついた手順しか確かめない。エージェントは、動いているアプリを自分で開かずに「通った」と報告できてしまう。

## 決定

- **完了の定義は 1 つで、`.claude/rules/definition-of-done.md` に置く。** PBI を閉じてよいのは、そこに書いた全部を満たしたときだけ
- **完了の定義を、全ての PBI の本文に「完了の定義」の節として書く。** 閉じるときに、その節の項目に 1 つずつチェックを入れる。ルールを読みに行かなくても、issue だけで何を済ませれば閉じてよいかが分かる
- **完了の定義に、ブラウザでのテストを 2 つ含める。どちらも省けない**

| 種類 | すること | 残す記録 |
|---|---|---|
| 自動のブラウザのテスト | その PBI の受け入れ条件のうち画面で観測できるものを、全部 Playwright のテストにする。CI で Chromium・Firefox・WebKit の 3 つで通す | CI の実行の URL |
| ブラウザでの実際の操作 | `pnpm build && pnpm start` で動かしたアプリを、本物のブラウザで開き、その PBI の変更を自分で操作する。1280px・768px・375px の 3 つの幅と、3 つのテーマのうち変更が関わるものを見る。コンソールのエラーと、失敗した通信が無いことを確かめる | 開いた URL・幅・した操作・見えた結果・コンソールのエラーの数を、issue を閉じるコメントに書く |

- **画面を持たない PBI にも適用する。** 文書だけの PBI は、GitHub の上で表示された文書をブラウザで開き、表・リンク・コードの枠が崩れていないことを確かめる。サーバーだけの変更（Route Handler・Server Action）は、その変更を使う画面を操作して確かめる。使う画面がまだ無ければ、ブラウザから直接その URL を開く・呼ぶ
- ブラウザでの実際の操作には、Chrome DevTools の MCP か、Chrome を操作する拡張を使う。使えない環境では、Playwright を画面つき（`--headed`）で動かし、画面の写真とコンソールの記録を残す
- **実際の操作で見つけた不具合は、その PBI の中で直し、再現する Playwright のテストを足す。** 範囲の外の不具合は、根本原因を書いた PBI にする（ADR-0003）
- 開発のサーバー（`pnpm dev`）だけでの確認は、完了の確認として数えない。本番のビルドで確かめる
- 記録の無い「確かめた」は、確かめていないものとして扱う

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 自動のテストと、実際の操作の両方（採用） | 自動のテストが後戻りを防ぎ、実際の操作が、テストに書かなかった崩れとエラーを見つける | PBI ごとに時間がかかる |
| Playwright だけ | 速い。繰り返せる | 書いた手順しか確かめない。見た目の崩れとコンソールのエラーに気づかない |
| 実際の操作だけ | 思いつかなかった問題を見つけられる | 次の変更で壊れても気づかない |
| 画面のある PBI だけに適用する | 文書の PBI が速い | 「画面があるか」の判断で抜け道ができる。ユーザーの「必ず」に反する |
| テストの工程でまとめて確かめる | PBI が速く閉じる | 不具合が、原因の変更から離れて見つかる |
| 開発のサーバーで確かめる | 起動が速い | Cache Components と `<Suspense>` の振る舞いが、本番のビルドと違う |

## 結果

- 閉じた PBI の全部に、ブラウザで何を見たかの記録が残る
- 完了の定義を変えるときは、ルールと、開いている全部の PBI の本文を同じ変更で直す
- PBI ごとに、本番のビルドと 3 つのブラウザでのテストの時間がかかる。CI は、ブラウザごとに並列にして縮める
- 「画面のテストが要るか」を PBI ごとに考えなくてよくなる
- CI の画面のテストは、失敗したときに、画面の写真と操作の記録（trace）を成果物として残す
