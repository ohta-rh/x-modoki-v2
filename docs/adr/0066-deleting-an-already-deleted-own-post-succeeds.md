# ADR-0066: もう消した自分の投稿の削除は、やり直しとして成功を返す

- ステータス: 置き換え: ADR-0067
- 日付: 2026-11-19
- 決定者: エージェント（委任された判断。ADR-0028 によりユーザーに聞かずに決めた）
- 関連: #84、#34、ADR-0064、#20

## 背景

- #70 で、通信の失敗は文言を出して画面を保つようにした。削除の応答だけが失われると（サーバーは消した）、もう一度「削除」を押したときに `deletePost` が `NOT_FOUND` を返し、画面は「この投稿は見つかりません」のまま止まった（#84、2026-11-19 に 3 回再現）
- #20 は、同時の削除で数が 1 回だけ減ることを確かめ、2 回目以降を `NOT_FOUND` にしていた
- 投稿の作成のやり直しは ADR-0064 で 1 つにまとめた

## 決定

- **作者が、もう消した自分の投稿を消すと `{ ok: true }` を返す。** 数（投稿の数・親の返信の数）と通知はもう変えない。同時の削除で更新が 0 行だったときも成功
- 無い投稿と、他人の消された投稿は、今までどおり `NOT_FOUND`。他人の消えていない投稿は `FORBIDDEN`

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **サーバーで、もう消した自分の投稿を成功にする（採用）** | どの画面も同じ結果を受け取る。別のタブで消したあとも同じ | 「もう消えていた」と「今消した」を、結果で見分けない |
| 画面で `NOT_FOUND` を成功として扱う | サーバーを変えない | 無い ID と他人の投稿の `NOT_FOUND` まで成功に見える |
| そのままにする | 手間が無い | 通信の弱い所で、消えた投稿が画面に残り、再読み込みまで止まる |

## 結果

- 良くなること: 削除はやり直しても同じ結果になる。いいね・ブックマーク・リポスト・フォロー・固定（はじめから「こうする」を送る形）と、投稿の作成（ADR-0064）と合わせて、全ての変更がやり直しに耐える
- 受け入れる負担: 作者は、消えていた投稿の削除が成功したように見える（結果は同じ）
- 守ること: 新しい変更の操作を足すときは、応答だけが失われたやり直しで同じ結果になるかを確かめる
