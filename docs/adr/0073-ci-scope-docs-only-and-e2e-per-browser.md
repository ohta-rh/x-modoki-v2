# ADR-0073: CI は範囲を決めてから動き、文書だけなら軽い確認、それ以外は画面のテストをブラウザごとに同時に流す

- ステータス: 採用
- 日付: 2026-11-20
- 決定者: ユーザー（文書だけの commit の扱い、2026-11-20）／エージェント（ブラウザごとのジョブ、判定の作り）
- 関連: ADR-0070（置き換える）、ADR-0069、ADR-0046、ADR-0047、ADR-0074、[ハーネスの見直し](../research/harness-review-2026-11.md)

## 背景

- ADR-0070 は、全部の push で 8 つの確認を 1 つのジョブで順に流すと決めた。画面のテストは 3 つのブラウザを順に流し、1 回の CI は約 20 分になった
- マイルストーン 1 の CI の実行 123 回のうち 69 回（56%）は、文書だけの commit（試験レポート・ADR・README）だった。そのための全部の確認は合計 419 分。コードが変わらないので、画面のテストの結果も変わらない（[ハーネスの見直し](../research/harness-review-2026-11.md) の 1 節）
- 同じブランチに続けて push すると、前の実行は取り消される（`cancel-in-progress`）。直前の commit と比べるだけでは、取り消されたコードの commit が確かめられないまま残りうる

## 決定

- **`scope` のジョブが最初に決める**（`scripts/ci-scope.mjs`）。祖先を新しい順に見て、`verify` と 3 つの `e2e` のジョブが全部通った最初の commit を基準にし、そこからの変更が全部文書（`docs/`、`.claude/`、`README.md`、`CHANGELOG.md`、`CLAUDE.md`、`LICENSE`）なら `docs`、それ以外は `full`。基準が無い、読めない、のどれでも `full`
- 変更の一覧は、名前の変更を分けて読む（`git diff --no-renames -z`）。`src/` から `docs/` へ移したファイルは、消えた道も出るので `full` になる。PR では、PR の基準の commit が、全部が通った commit の祖先でなければ `full`（基準のブランチが進んだあとのマージは、まだ確かめていない）
- **`docs:check` の外の確認が読む文書は、コードとして扱う**（`GATE_INPUTS`: 脅威のモデルは `check-authz` が、手順書と `.claude/settings.json` は `scripts/quality-gates.test.ts` が読む）。確認が新しい文書を読み始めたら、`scripts/ci-scope.test.mjs` がスクリプトとテストの中の読み込みの道を探して落ちる
- **`docs`**: `pnpm docs:check`（要件とテストの結びつきを含む）と `pnpm format:check` だけを流す
- **`full`**: ADR-0070 の 8 つの確認を全部流す。`verify` のジョブが依存の監査と確認 1〜6、`e2e (chromium)`・`e2e (firefox)`・`e2e (webkit)` の 3 つのジョブが確認 7 を、同時に流す。各ジョブは自分でビルドする
- `fresh-clone`（ADR-0069）は、手順書も文書なので、全部の push で流す
- ADR-0070 のほかの決定（落ちたら失敗、CI が緑でない変更は完了でない、push の前に `pnpm verify`、`main` が赤なら最優先、確認を弱めない、監査は依存を上げて直す）は全部引き継ぐ
- 文書として扱う範囲を広げることは、確認を変えることなので、ユーザーが決める

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **全部が通った commit を基準に範囲を決め、ブラウザごとに同時に（採用）** | 文書だけの push は数分。コードの push は 20 分から 10 分前後に。確認は減らない。取り消された commit も見逃さない | GitHub の API を読む判定のスクリプトが増える。ランナーの分は 4 つに増える |
| 全部の push で全部を順に（ADR-0070 のまま） | 一番単純 | 待ちが長い。CI の半分以上が結果の変わらない確認 |
| 直前の commit との差分で決める（`paths-ignore`） | 単純 | 取り消された実行のコードを見逃す |
| 試験レポートを次の push に乗せる | CI の回数が減る | issue を閉じるのが 1 件分遅れる。確認の形は変わらない |

## 結果

- 良くなること: 文書だけの push は数分で終わる。コードの push も、画面のテストが同時に流れるので短くなる。落ちたブラウザがジョブの名前で分かる
- 受け入れる負担: 判定のスクリプトとそのテスト。全部の確認のジョブの名前は `scripts/lib/ci-scope.mjs` の `FULL_JOBS` と一致させる（`scripts/quality-gates.test.ts` が確かめる）
- 守ること: 文書の範囲を広げない（広げるならユーザーが決め、新しい ADR を書く）。ジョブの名前を変えたら `FULL_JOBS` も同じ変更で変える
